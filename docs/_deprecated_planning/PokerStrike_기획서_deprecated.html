소개용 핵심 메시지

PokerStrike는 “포커를 잘 치는 게임”이라기보다 “포커 패를 전투 자원으로 해석하는 게임”이다. 플레이어는 매 웨이브마다 핸드와 공용 카드를 보고 지금 강한 유닛을 뽑을지, 마법으로 위기를 넘길지, 골드를 써서 패를 바꿀지 결정한다.

소개할 때는 아래 세 문장만 잡히면 된다.

  • 좋은 패는 강한 유닛이나 마법으로 바로 바뀐다.
  • 약한 패도 교체 비용, 배치 위치, 웨이브 타이밍으로 만회할 수 있다.
  • 한 판의 재미는 “이번 패로 어디까지 버틸 수 있나”를 빠르게 판단하는 데 있다.

30초 플레이 흐름

순서플레이어 행동화면에서 보여야 하는 것재미 포인트
1웨이브와 본진 HP를 확인한다상단 HUD, 적 진행 방향, 위험 알림지금 막아야 할 압박이 즉시 보인다
2핸드 5장과 공용 카드 2장을 읽는다카드, 족보 후보, 소환/마법 예측포커 판단이 전투 선택으로 연결된다
3소환, 마법, 교체 중 하나를 고른다선택 가능한 버튼과 비용좋은 패를 쓸지 더 좋은 패를 노릴지 고민한다
4전장이 즉시 반응한다유닛 배치, 공격, 피격, 마법 효과선택 결과가 바로 보상 또는 위기로 돌아온다
5웨이브 보상과 강화 방향을 고른다보상 선택지, 다음 웨이브 예고다음 판을 더 잘 풀기 위한 전략이 생긴다

잘못 기획되었는지 보기 쉬운 지점

점검 항목위험 신호판단 기준권장 조치
포커와 디펜스의 결합플레이어가 족보를 만들었는데 전투 결과가 약하게 느껴짐좋은 패일수록 화면 반응과 생존 기여가 명확해야 함족보별 유닛/마법 효과를 더 과장하거나 보상 차이를 키운다
교체 비용항상 교체가 정답이거나, 반대로 절대 누르지 않음비용이 웨이브 압박과 맞물려 선택지가 되어야 함교체 비용 증가폭과 골드 지급량을 함께 조정한다
공용 카드공용 카드 2장이 그냥 장식처럼 느껴짐플레이어가 매 턴 공용 카드를 근거로 결정을 바꿔야 함공용 카드가 마법/상위 족보에 주는 영향 설명을 강화한다
유닛 역할유닛이 다 비슷하게 공격하는 느낌각 족보 유닛의 사거리, 속도, 타겟팅, 특수성이 구분되어야 함역할별 대표 상황을 GDD와 테스트 케이스에 고정한다
소개 화면처음 보는 사람이 장르와 재미를 10초 안에 못 잡음카드, 전장, 족보 결과가 한 화면에 연결되어야 함문서 첫 화면과 게임 HUD의 정보 우선순위를 맞춘다

PR 체크리스트

  • □ 핸드 5장, 공용 카드 2장, 덱 재순환이 정상 동작한다.
  • □ 족보 판정 결과가 소환/마법 UI에 같은 용어로 표시된다.
  • □ 소환 전 예측과 소환 후 실제 유닛 결과가 어긋나지 않는다.
  • □ 마법 사용 조건, 비용, 효과 범위가 화면에서 설명된다.
  • □ 웨이브 시작, 종료, 본진 피해, 게임오버 판정이 테스트 가능하다.
  • □ 보상 선택이 다음 웨이브 전략을 바꿀 만큼 의미가 있다.
  • □ 문서 이미지와 실제 현재 구현 화면이 크게 어긋나지 않는다.

게임 구성과 규칙 (GDD 요약)

원본 GDD의 장점은 “무엇을 구현했는지, 무엇이 빠졌는지, 어떤 규칙이 충돌하는지”를 표로 빠르게 찾을 수 있다는 점이다. 이 기획서는 소개용 흐름을 먼저 보여주고, 아래에는 개발 점검에 필요한 규칙만 요약한다.

현재 개발 상태 예상 수치

아래 수치는 성공 KPI가 아니라, 현재 구현/문서/이미지 상태를 기준으로 본 “지금 소개하거나 PR할 때의 체감 완성도 추정”이다. 실제 플레이 테스트 후 보정이 필요하다.

항목현재 예상근거
핵심 루프 전달력약 72%카드 선택, 전투, 웨이브 구조는 설명 가능하지만 성장 보상 설명이 약함
소개용 설득력약 64%이미지와 한 줄 콘셉트는 있으나 실제 재미 포인트를 더 짧게 보여줘야 함
개발 점검 용이성약 68%체크리스트와 불일치 항목을 추가했지만 테스트 링크/자동 검증은 더 필요함
UI/피드백 완성도약 60%현재 구현 화면 기준으로 정보는 있으나 시선 우선순위와 결과 예측 표시가 더 필요함
반복 플레이 기대감약 54%보상/성장/빌드 변화가 아직 문서와 구현에서 가장 약한 축

현재 구현 상태

  • 기준 버전: 0.1.64
  • 실행 형태: Phaser 3 기반 웹 게임과 Electron portable 배포 구조.
  • 현재 강점: 카드 기반 판단과 디펜스 전투를 한 화면에 묶는 핵심 방향이 명확하다.
  • 현재 약점: 소개용 문장, 보상/성장 설계, PR 점검 기준이 충분히 분리되어 있지 않았다.
  • 이번 문서 정리 방향: 처음 1분은 소개용, 이후 섹션은 개발 점검용으로 읽히게 분리한다.

문서 운영 규칙

  • 소개용 문장은 문서 상단에 유지하고, 변경 이력은 업데이트 내역서로 분리한다.
  • GDD 전체를 복붙하지 않고, 개발자가 점검해야 할 규칙만 요약한다.
  • 공유용 이미지는 본문에 직접 삽입해 HTML에서도 바로 보이게 유지한다.
  • 성공 KPI 대신 현재 개발 상태 예상 수치를 쓰고, 실제 플레이 테스트 후 수치를 갱신한다.
  • GDD 원본은 삭제하지 않고 상세 규칙 참고용으로 남긴다.
