# PokerStrike 게임 디자인 문서 (GDD)

![PokerStrike gameplay preview](./PokerStrike_gameplay_preview.png)

**버전**: v1.0.2 (문서 갱신일: 2026-09-11 KST)
**엔진/플랫폼**: Phaser 3 + Electron (데스크톱)
**장르**: 카드 핸드 기반 타워 디펜스

## 문제 정의

배치 후 관망이 길어지는 타워 디펜스에서, 매 웨이브마다 카드 조합 판단과 배치 결정을 요구해 의사결정 밀도를 유지한다.

## 주 페르소나

- **민준, 31세, 사무직**: 퇴근 뒤 20~30분 동안 짧지만 계산할 거리가 있는 디펜스 게임을 찾는다. 공개된 카드 2장을 보고 지금 조합을 확정할지 다음 웨이브를 버틸지 판단하는 순간에 가치를 느낀다.

## 핵심 루프

플레이어가 공유 카드와 손패로 포커 핸드를 만들면 등급 배율이 적용되고, 그 결과로 방어를 배치·강화한 뒤 웨이브 결과를 바탕으로 다시 다음 조합을 판단한다.

## 디자인 기둥

1. **판단의 밀도**: 매 웨이브 카드 조합과 배치라는 개입 지점을 만든다.
2. **투명한 확률**: 핸드·등급·배율을 명확히 보여 블랙박스를 피한다.
3. **패배도 정보**: 낮은 핸드에서도 다음 배치와 자원 판단으로 회복할 여지를 둔다.

## MVP 가설

| 가설 | 검증 방법 |
|---|---|
| 공유 카드 2장과 등급 배율만으로 재플레이 동기가 생긴다 | 초반 스테이지 완료율·재시작률 측정 |
| 9종 핸드는 첫 3스테이지 안에 학습된다 | 핸드 도움말 노출과 이탈 웨이브 기록 |
| 1/1.8/3.2 배율이 희귀 조합의 기대감을 만든다 | 핸드 분포와 세션 길이 비교 |

## 레퍼런스 분석

| 레퍼런스 | 핵심 행동까지 단계 | 적용 교훈 |
|---|---:|---|
| 포커의 공유 카드 | 공개 → 조합 → 판정 (3단계) | 제한된 공용 정보가 짧은 계산을 만든다. |
| 타워 디펜스 | 배치 → 전투 → 보상 (3단계) | 전투 전 판단과 전투 후 결과를 분명히 분리한다. |

## 구성요소

| 구성요소 | 역할 | 플레이어 선택 | 입력 → 판정 → 피드백 | 구현 상태 |
|---|---|---|---|---|
| 공유 카드 | 웨이브 공통 정보 | 없음 | 2장 공개 → 조합 재료 제공 → 카드 UI | 구현됨 |
| 손패·핸드 판정 | 조합 가치 산출 | 사용할 카드 선택 | 카드 선택 → 9종 랭크 판정 → 랭크·등급 표시 | 구현됨 |
| 등급 배율 | 보상/전투 수치 증폭 | 확정 타이밍 | 등급 1~3 → 1/1.8/3.2배 → 수치 변화 | 구현됨 |
| 방어 유닛·그리드 | 방어선 구성 | 위치·유닛 선택 | 배치 입력 → 자원·위치 검증 → 가능/불가와 전투 피드백 | 구현됨 |
| 웨이브 | 위협·결과 생성 | 방어 준비 | 적 출현 → 전투 판정 → HP·처치·승패 | 구현됨 |

## 실제 콘텐츠와 공급 순서

- 공유 카드: 웨이브당 **2장**.
- 핸드: 하이카드부터 스트레이트 플러시까지 **9종**.
- 수트: **4종**, 등급: **1~3**, 배율: **1 / 1.8 / 3.2**.
- 스테이지: 장애물 배치가 다른 **10개**. 스테이지당 **3~6웨이브**.
- 적: basic, swarm, runner, boss, armored, berserker, shielded, aerial, magic_immune, splitter, regen의 **11종**.
- 공급 순서: 카드 공개 → 핸드/등급 판정 → 배치·강화 → 웨이브 전투 → 결과와 다음 웨이브. 정확한 자원 획득량·해금 조건은 **확인 필요**다.

## 세션 페이싱과 재미 체인

- **30초**: 공개 카드 확인, 조합 판단, 등급·배율 확인.
- **5분**: 하나 이상의 웨이브에서 배치와 결과를 반복.
- **30분**: 3~6웨이브 스테이지를 마치고 다음 장애물 패턴에 대응.
- **장기**: 10개 스테이지와 핸드·적 조합의 숙련을 축적.

**재미 원천 → 발생 조건 → 판단/행동 → 즉시 피드백 → 반복 동기**: 불확실한 카드 조합 → 공유 카드 2장 공개 → 핸드를 골라 방어선에 투자 → 랭크·배율·전투 결과가 즉시 표시 → 다음 웨이브에서 더 좋은 전환과 회복을 시도한다.

## 플레이 사례

1. 플러시가 가능한 공유 카드를 보고 손패를 확정해 1.8배 결과를 얻고, 다음 swarm 웨이브 전 광역 대응 유닛을 배치한다.
2. 하이카드만 나온 상황에서는 과투자를 피하고 기본 방어를 유지한다. 일부 피해 뒤 다음 공개 카드로 원페어 이상을 만들어 부족분을 보완한다.

## 실패·피로와 완화

- 같은 판정 화면 반복은 피로를 만든다. 11종 적의 대응 차이와 10개 장애물 패턴으로 판단 대상을 바꾼다.
- 낮은 핸드가 연속되면 무력감을 줄 수 있다. 기본 수급만으로도 진행 가능한지 검증하고, 고등급은 가속 보상으로 설계해야 한다(수치 **확인 필요**).

## 경제·성장·밸런스 레버

배율 1/1.8/3.2, 핸드 발생 분포, 적 조합·웨이브 수, 장애물 배치가 핵심 레버다. 유닛·자원 비용과 실제 배율 적용 대상은 **확인 필요**이며, 후반을 고배율 의존으로 만들지 않는 검증이 필요하다.

## 온보딩·UI/HUD·접근성

- 온보딩: 첫 스테이지에서 공유 카드 → 핸드 판정 → 배치 순서로 한 단계씩 보여 준다(제안).
- HUD 5상태: 카드 공개 전, 조합 선택, 판정 결과, 전투 진행, 승패 결과.
- 로딩은 스켈레톤, 빈 상태는 안내+CTA, 오류는 원인·재시도, 많은 데이터는 스크롤/요약, 긴 텍스트는 줄바꿈을 제공해야 한다(제안·구현 확인 필요).
- 수트 색상만으로 구분하지 않고 아이콘·패턴·텍스트를 병기한다. 고등급에는 더 분명한 음향·시각 큐를 둔다.

## 구현 / 기획 / 제안

- **구현됨**: 공유 카드 2장, 9종 핸드, 4수트, 3등급 배율, 10스테이지·3~6웨이브, 11종 적, game/UI/audio/combat/economy 테스트.
- **기획 확인 필요**: 자원 공식, 유닛 해금·비용, 난이도 증가율, 실제 계측.
- **제안**: 초반 핸드 튜토리얼, 색각 보조, 고등급 피드백 강화.

## 성공 KPI

**제안(현재 실측 데이터 없음, 검증 필요):**

- **포뮬러 명확성**: 9종 포커 핸드 × 등급 배율(1 / 1.8 / 3.2) 조합에 대한 플레이어 이해도 — 튜토리얼 완료 후 정답률 또는 핸드-배율 매칭 퀴즈 정답률(제안 목표 ≥80%)
- **분석(Analytics) 적재율**: 10개 스테이지 × 웨이브(3~6) 단위 진행 이벤트, 공유 카드(cards2) 사용 로그, 적 타입(11종) 조우 이벤트의 수집 성공률(제안 목표 ≥99%)
- **온보딩 완주율**: 신규 유저의 스테이지 1 완료율 및 첫 세션 내 핵심 룰(공유 카드, 배율 시스템) 노출 도달률
- **접근성 준수율**: 색맹 모드/텍스트 대체 등 접근성 옵션 적용 후 UI 요소 인지 테스트 통과율
